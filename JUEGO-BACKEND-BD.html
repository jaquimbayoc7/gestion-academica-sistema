Nivel 1 — Prisma Schema y Relaciones en la BD

Comprende cómo Prisma mapea modelos TypeScript a tablas SQL en PostgreSQL.

1
¿Qué hace @@map("estudiantes") en el modelo Prisma?
Schema Prisma → Tabla SQL
En schema.prisma, el modelo Estudiante tiene @@map("estudiantes") al final. ¿Para qué sirve?
💡 Pista: Prisma usa PascalCase en el modelo TypeScript pero la tabla real en PostgreSQL se llama "estudiantes" en snake_case gracias a @@map.
2
¿Qué tipo de relación hay entre Matrícula y Calificación?
Relaciones en el Schema
El modelo Matricula tiene calificacion Calificacion? y Calificacion tiene matriculaId Int @unique. ¿Qué tipo de relación es?
💡 Pista: Cuando el campo FK tiene @unique, Prisma crea una relación 1:1. El ? en Calificacion? indica que es opcional: las notas se registran después de la matrícula.

4
¿Para qué sirve @@unique([docenteId, asignaturaId, periodoAcademicoId])?
Restricción UNIQUE compuesta
En el modelo AsignacionDocente, se usa una restricción UNIQUE compuesta con 3 campos. ¿Qué evita?
💡 Pista: La combinación de los 3 campos (docenteId + asignaturaId + periodoAcademicoId) debe ser única. Un docente SÍ puede dictar la misma materia, pero en períodos diferentes.

Nivel 2 — Repository: Consultas Prisma a la BD

Los Repositories encapsulan todas las consultas a PostgreSQL usando Prisma Client.

5
¿Qué hace include en una consulta Prisma?
Relaciones y JOINs SQL
En estudiantes.repository.ts, el método findAll() usa:
prisma.estudiante.findMany({ include: { programaAcademico: true } })
¿Qué operación SQL equivale?
💡 Pista: include: { relacion: true } trae los datos relacionados en la misma consulta, como un LEFT JOIN en SQL.

7
¿Por qué el Repository de Calificaciones usa include anidado?
Nested includes = JOINs múltiples
El calificaciones.repository.ts usa:
include: { matricula: { include: { estudiante: true, asignacionDocente: { include: { asignatura: true, docente: true } } } } }
¿Qué logra este include anidado?
💡 Pista: Los includes anidados equivalen a múltiples LEFT JOINs encadenados: calificaciones → matriculas → estudiantes + asignaciones_docente → asignaturas + docentes.

Nivel 3 — Service: Lógica de Negocio y Errores Prisma

El Service contiene la lógica de negocio y maneja los errores que Prisma lanza desde la BD.

9
¿Qué error Prisma se produce al duplicar un campo @unique?
Error P2002
Si intentas crear dos estudiantes con el mismo codigoEstudiantil, Prisma lanza un error. ¿Cuál es su código?
💡 Pista: P2002 = UNIQUE constraint violation. P2003 = FK constraint violation. El Service convierte P2002 en ConflictException (HTTP 409).

12
¿Qué pasa si intentas eliminar un Programa que tiene Estudiantes?
Error P2003 — Foreign Key
Si intentas DELETE FROM programas_academicos WHERE id = 1 pero hay estudiantes con programaAcademicoId = 1, ¿qué ocurre?
💡 Pista: Las Foreign Keys protegen la integridad referencial. No puedes borrar un padre si tiene hijos. El error P2003 indica violación de FK.
